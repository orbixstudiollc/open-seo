# Phase 7 reports, export, sharing, and digests build report

Produced 28 Jul 2026 for `phase-7-reports-share-digests`.

## Shipped

- A project-scoped **Reports** page at `/p/$projectId/reports`, linked under
  **My Site**, with 7, 30, and 90-day periods.
- One versioned report contract built from the Phase 2 visibility overview and
  Phase 5 citation intelligence services using a shared `asOf` clock. The
  contract exposes summary metrics, platform visibility, top cited domains,
  and competitor-source gaps from stored runs only.
- Authenticated PDF export through `/api/reports/export`. The route validates
  the query boundary, authorizes the project against the caller's organization,
  and returns a real A4 `application/pdf` attachment generated by `pdf-lib`.
- Expiring manual share links and seven-day digest links through
  `/share/<token>` and `/share/<token>/report.pdf`.
- Weekly email-digest settings per project and user. Due rows are conditionally
  claimed and advanced before delivery, then sent through a dedicated Loops
  transactional template from the existing Phase 1 scheduled handler.
- D1 migration `0042_amused_zzzax.sql` and Postgres migration
  `0019_next_luke_cage.sql`. They add normalized `report_shares` and
  `report_digest_schedules` tables and ship together.
- Deployment bindings and self-hosting documentation for the public report
  origin, digest template, and the explicit `local_noauth` share-only opt-in.

The report page uses the existing `--visibility-*` design tokens. No
recommendation code or existing page styling changed.

## Security verification — signed off

Security review is complete with no open Phase 7 finding.

- Share tokens contain 32 Web Crypto random bytes, encoded as a 43-character
  base64url bearer. Only a SHA-256 digest is stored; owner listing responses
  explicitly map their fields and do not return that digest.
- Every public request hashes the exact-shape token and resolves one share row
  joined to the same active project and organization. It requires report
  contract version 1, `revoked_at IS NULL`, and `expires_at >` the request's
  single server-side clock.
- The public URL contains no project, organization, period, report, or child
  resource selector. Any query string is rejected. Repository fixtures cover
  two projects in one organization and a second organization, plus an
  organization-mismatched share row.
- Malformed, unknown, expired-at-the-boundary, revoked, mismatched-organization,
  and archived-project tokens all produce the same not-found result. Revocation
  is effective on the next request.
- A separate Playwright browser context started with zero cookies and loaded
  the live link successfully. It made one document request, displayed the
  intended `Default` project, set no cookie, contained no bearer token or
  script, rejected `?projectId=another-project` with 404, downloaded the
  token-scoped PDF, and returned 404 immediately after owner revocation.
- Public responses are static and set `no-store`, `no-referrer`, `nosniff`,
  `DENY`, `noindex/nofollow/noarchive`, and a `default-src 'none'` CSP. Public
  share requests bypass installation telemetry as well as app authentication,
  MCP, agents, providers, workflows, billing, activation, and cache refreshes.
- The public DTO is an explicit Zod allowlist. Tests prove that project/brand
  IDs, exact citation URLs, raw answers, provider payloads, and newly added
  service fields do not pass through.
- Digest delivery redacts provider error details that could contain the report
  URL. A newly created digest link is revoked if email delivery fails, and only
  a bounded `delivery_failed` code is persisted.
- `local_noauth` sharing remains disabled unless
  `REPORT_PUBLIC_SHARE_MODE=share_only` is set. The Docker guide now states the
  binding security conclusion explicitly: exposing the whole no-auth origin is
  unsafe because it also exposes the local-admin app and MCP surface. Only a
  share-only origin or proxy carve-out is supported for anonymous recipients.
